# V3.4 result — buffer lifetime and display phase

Measured on the 1920×1080 ~60 Hz development configuration with the stable four-buffer pool:

| Measurement | Approx. median |
|---|---:|
| previous OUT → DQ | 0.041 ms |
| previous OUT → commit | 0.101 ms |
| DQ → commit return | 0.060 ms |
| commit return → OUT | 16.565 ms |
| own OUT → QBUF | 16.625 ms |

Historical analysis also observed roughly 33.345 ms from QBUF to same-buffer DQ and roughly 66.666 ms same-buffer reuse on that run.

## Interpretation

A capture frame becomes available almost immediately after the preceding display completion, and userspace submits the next atomic update within tens of microseconds. The update then waits almost a complete ~60 Hz display period for its own OUT fence. Buffer ownership is cadence-quantized as well.

Therefore the useful next experiment is not micro-optimizing DQ/commit code. It is testing display-phase bypass (`DRM_MODE_PAGE_FLIP_ASYNC`) and, if necessary, explicit source/output phase control.
