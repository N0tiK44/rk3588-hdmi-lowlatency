# Development history

## V3.7.1 — reproducible one-command workflow

Added a guarded Pi bootstrap that fast-forwards `main`, validates/builds the
source, runs a selected experiment and always packages machine-readable results.
Added a PowerShell fetch helper with a stable `latest.tar.gz` remote path. This
is a workflow release only; the V3.7 datapath is unchanged.

The V3.7 hardware result was also recorded: matching the advertised 59.940 Hz
mode reduced the observed two-vblank cadence slips from seven to one and
extended the theoretical beat period from 16.544 seconds to 1,354.377 seconds,
with no capture gaps or missing fences.

This repository was reconstructed from the historical project packages and intentionally replaces the old patch-chain layout with one current source file.

## Consolidation decisions

### One C source, no patch chain

The current `src/hdmirx-kms-lowlat.c` is based on the proven V2 direct path with the V3.1 measurement instrumentation, V3.4 QBUF lifetime timestamping, V3.5 async diagnostic, V3.6 phase profiler and V3.7 advertised-mode experiment integrated directly. Historical `apply-v3*.py` scripts are not required and are not shipped.

### V3.5 historical patcher mismatch

The supplied V3.5 patch script expected an option-structure text anchor that does not match the V3.1→V3.4 source generated by the supplied historical patchers. More importantly, merely adding `DRM_MODE_PAGE_FLIP_ASYNC` to the existing full atomic request is not a valid async flip: the request changes `OUT_FENCE_PTR` and repeats plane state that async atomic commits do not permit. It would also try to async-enable a fresh plane without first establishing normal state.

The consolidated experiment instead capability-checks the DRM device, seeds the plane with one normal commit, submits only `FB_ID` plus `IN_FENCE_FD` on later async commits, and waits `DRM_MODE_PAGE_FLIP_EVENT` completion. Unsupported kernels/drivers now return a real failure status rather than being hidden by the runner.

### CSV newline cleanup

The V3.1-generated instrumentation contained escaped newline text in several emitted strings, which is why later analyzers included a repair path for a whole CSV appearing as one physical line. The consolidated writer emits proper newline characters. `tools/analyze.py` retains old-trace repair so previously captured data can still be inspected.

### Historical GStreamer test is not the active architecture

The earliest FD test used `v4l2src io-mode=dmabuf ! kmssink` to exercise the platform and watch `sync_file` descriptors. It remains useful historical evidence, but the current repository deliberately uses the direct C V4L2/DRM path and has no GStreamer dependency.
