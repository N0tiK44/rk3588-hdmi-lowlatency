# V3.8 early-submission experiment

Status: completed negative result; experiment retired.

V3.7 removed the material input/output cadence mismatch but retained the normal
approximately one-vblank atomic completion interval. V3.8 keeps that verified
59.940 Hz mode and performs one controlled overlap probe after warm-up.

Expected Linux 6.1 Rockchip result: the second nonblocking atomic commit is
rejected with `EBUSY` while the first flip is pending. The experiment then waits
the candidate producer fence, returns that capture buffer, annotates the one
intentional sequence gap, and continues measuring. This distinguishes kernel
serialization from userspace submission time without weakening DMA-BUF or fence
ownership.

An equally meaningful outcome is that every current OUT fence signals before
or at the same poll wakeup as the next capture DQ. In that case no overlap is
attempted and no frame is dropped: the trace has directly shown that the
present capture/display phase exposes no early-submission window.

Hardware result (`000c4fef0bad`, Linux `6.1.115-vendor-rk35xx`):

- overlap attempts: 1;
- overlap result: `EBUSY`;
- intentional drops: 1;
- raw sequence gaps: 1, intentional: 1, unexpected: 0;
- next recorded frame: sequence 122 after sequence 120;
- that next commit advanced two vblanks and took approximately 31.93 ms from
  commit to OUT;
- high-speed video showed the passthrough become approximately one frame later.

The relevant frame's DQ occurred after the CRTC sequence had already advanced,
demonstrating that OUT-fence notification lag—not a genuine pre-latch window—
won the userspace poll race. V3.8.1 removes the drop and classifies with the
actual CRTC sequence.
