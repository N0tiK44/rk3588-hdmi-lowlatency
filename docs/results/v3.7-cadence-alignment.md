# V3.7 cadence-alignment experiment

## Hypothesis

The periodic 32 ms completions are cadence slips caused by a roughly 59.94 Hz HDMI-RX stream running against the Orange Pi's exact 60.000 Hz CRTC mode. Selecting an EDID-advertised 59.94 Hz output timing should reduce or remove these rare two-vblank waits without affecting the normal explicit-sync datapath.

## Controlled A/B

The runner records two 120-second arms:

1. unchanged active output timing;
2. `59940` millihertz using a matching advertised 1920×1080 connector mode.

Both arms use four capture buffers, NV24 DMA-BUF scanout, Rockchip low-latency acquire fences, plane `IN_FENCE_FD`, CRTC `OUT_FENCE_PTR`, and the V3.6 phase instrumentation. The second arm restores the startup CRTC mode on exit.

## Pass criteria

- reference behavior reproduces without sequence gaps or missing fences;
- aligned arm confirms the requested timing was applied;
- original timing is restored after the aligned arm;
- aligned arm has zero capture sequence gaps and zero missing fences;
- two-vblank completions and timestamp sawtooth wraps are materially reduced;
- normal completion cadence and four-buffer ownership remain stable.

The experiment may still be informative if unsupported. If no advertised 59.94 Hz mode exists or the driver rejects the atomic modeset, retain the log and do not synthesize a custom mode.

## Non-goal

V3.7 is a consistency experiment. It is not expected to eliminate the normal approximately 16.55 ms commit-to-OUT interval. Submission/ownership changes belong to a later isolated version.
