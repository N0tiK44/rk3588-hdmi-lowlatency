# V3.6 phase-profiler result

## Question

Does capture dequeue consistently miss the current display latch window, and how does the HDMI-RX cadence drift relative to the active CRTC vblank clock?

The high-speed-camera control measured roughly 16 ms between the directly connected Windows displays and roughly 33 ms through the Orange Pi path. The difference is consistent with the measured ~16.566 ms KMS commit-to-OUT interval. V3.6 tests that phase hypothesis without altering the datapath.

## Run

```bash
sudo bash ./scripts/run-v36-phase-profiler.sh
```

Defaults: 120 seconds, four buffers, `/dev/video0`, `/dev/dri/card0`, connector 217, plane 114. Files are written to `/tmp/hdmirx-v36/`.

During the run, record a 240 fps slow-motion clip containing both the direct reference display and passthrough display. Use a full-screen millisecond counter or alternating black/white frame marker. Keep Windows in duplicate mode and note which GPU/port drives the reference display.

## Pass criteria

- program exits zero and reports `runtime status: completed`
- four buffers allocated and no V4L2 sequence gaps
- zero missing Rockchip acquire fences
- V4L2 timestamp type reported as monotonic
- `phase profiler samples` equals the recorded sample count
- CSV, log and report are non-empty
- baseline cadence remains near 16.67 ms

## Interpretation

- `commit -> predicted vblank` near `commit -> completion` supports a vblank-latch wait.
- `commit -> OUT vblank steps` near 1 supports one display-period ownership delay.
- steadily changing unwrapped DQ/display phase indicates a small capture/output clock mismatch; its ppm sign and magnitude inform a later refresh-offset experiment.
- stable phase with a one-step completion delay points toward driver latch/ownership behavior rather than clock drift.

## Hardware result

The 120-second trace produced 7,126 post-warmup rows with zero V4L2 sequence gaps and zero missing Rockchip fences. Normal commit-to-OUT completion was 16.552 ms median. DQ and commit occurred approximately 0.088 ms and 0.099 ms after vblank respectively.

Raw-trace inspection found eight two-vblank completions of approximately 32.52 ms. They were spaced 978–980 frames apart. The HDMI-RX EOF timestamps measured approximately 59.94 Hz while the active 148.500 MHz CRTC mode measured exactly 60.000 Hz. Timestamp-to-DQ age formed a repeating sawtooth and reset at each two-vblank event.

The original analyzer's endpoint-based `unwrapped DQ/display drift` value hid this repeating wrap and must not be used as the V3.6 conclusion. The V3.7 analyzer replaces it with input/output frequency, theoretical beat period, timestamp-wrap count, two-vblank count and event spacing.

The camera control remains important: the host's separate dGPU/iGPU outputs are already approximately 16 ms apart. The approximately 33 ms side-by-side passthrough observation is therefore consistent with that host offset plus the Pi's normal one-vblank delay.

V3.6 did not change refresh, mode timing or scanout policy. V3.7 separately tests an EDID-advertised 59.94 Hz output mode.
